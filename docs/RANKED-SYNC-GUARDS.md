# Ranked supply and saved history

The server issues a separate roll tape for each registered player/binder epoch. It is not a shared pool across the community. Refills now add 10,000 attempts at the existing 250-entry threshold. Misses use entries too; finding a pack reuses the attempt entry and opening a pack uses one entry per card. Supply reaches the game through Data/Sync.lua on UI reload or launch. It cannot be injected into a running addon without reloading.

A saved position earlier than the supplied start is not exhaustion. During investigation, the inspected local file had next=1 while Sync.lua started at 96 with 905 entries. Files reflect the last game save, not live game memory. The app now detects empty/short histories against cached acknowledgements and probes once on a cold start when no events remain. A fully pruned matching head is accepted; a same-position different hash is refused. A zero server acknowledgement is cached internally but is not written as a pruning instruction.

The engine clears incompatible cached supply and does not request another tape when the Ranked binder cannot sync. A response starting past the local next position is withheld too. The account displays a specific mismatch, and Sync.lua carries a bounded rankedIssue value so the addon explains the problem rather than saying all rolls were spent. Missing supply, genuine exhaustion and an outdated addon have distinct messages. A matching restored save can resume without a reset. Cards, packs, settings, local files, server history, tape positions and epochs are never automatically rewritten to reconcile a mismatch.

Regression tests cover warm/cold starts with an empty replacement binder, matching pruned saves, differing head hashes, cached zero acknowledgements, next=1 versus start=96, withholding old supply, and resuming from a restored matching position. The save-driven runner retains its idle request and retry tests; no periodic polling was added. This does not recover already missing local history or prevent someone from manually replacing program/save files; it makes those conflicts explicit and protects the surviving data.
