# Collectible boss editions

The first batch adds sixteen collectible variants across four dungeons. Ordinary set slots remain unchanged: any edition of a creature counts for that creature. Variants are optional extras, with separate copies, spare counts and holographic unlocks.

## Presentation and binder controls

Rarity icons have moved from the nameplate onto the divider at y=140, between the rarity line and description. Common uses a circle, Rare a square, Epic a diamond and Legendary a hexagon. A special edition uses a star in its rarity colour. These are tintable native TGA silhouettes, generated by `node tools/make-rarity-icons.js`. The four frame designs retain their palette and decoration.

Boss details have three edition buttons below the large card. Each shows its own count or Locked. A locked edition may be previewed in grey without granting it. Clicking a chat link selects that exact edition. Shift-click, trade selection, wanted lists and binder inspection carry its exact inventory key. Thumbnail models remain still; owned animated details can play, pause and rotate with the existing controls. Unsupported animations fall back to a still frame. Camera framing and timings still require a Forever playtest.

### Revised compositions in 0.4.0

Every still and animated edition now has an authored action, a substantially different facing and crop from Signature, its own frozen point, and a small camera offset. The original Signature assignments remain unchanged. The composition notes are shown in `/acb studio`.

| Boss | Still composition | Animated composition |
| --- | --- | --- |
| VanCleef | Wide side-on stealth crouch | Opposite-side spinning blade attack |
| Mr. Smite | Tight roaring profile | Wide full-body hammer strike |
| Arugal | Tight side-on spell preparation | Wide directed spell cast |
| Silverlaine | Wide kneeling ghost portrait | Tight spectral roar |
| Mograine | Close commanding salute | Wide sweeping weapon attack |
| Whitemane | Wide kneeling prayer | Tight arms-raised resurrection cast |
| Kelris | Close channeling profile | Wide ritual channel |
| Aku'mai | Side-on three-headed roar | Opposite wide creature-special attack |

Each profile includes alternative animation IDs for models missing the preferred action. A supported alternative can animate and continues using that action when the loop restarts; paused cards and thumbnails freeze on it. If none is supported, the neutral pose retains the edition's distinct framing. Foe Reaper's two existing studio previews also have contrasting close/wide action profiles; they remain previews, rather than new collectible keys.

These are authored first-pass compositions, verified against the renderer with API stand-ins. Actual silhouettes, clipping and animation timing must still be reviewed in Forever. Animation identifiers were checked against the [client animation definitions](https://github.com/TrinityCore/TrinityCore/blob/3.3.5/src/server/shared/SharedDefines.h), and guarded playback follows the [exported character-model API](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/FrameAPICharacterModelBaseDocumentation.lua).

## Initial drop rules

The existing source drop chance and bad-luck protection decide whether a card drops. On a successful drop from one of these eight sources, a second draw chooses the edition: 15% still variant, 5% animated variant, 80% Signature. These percentages are conditional on a card drop, not percentages per kill. The same rule applies after selecting a base card from a pack. Other sources are unchanged.

Each edition can independently unlock holographic finish, following the existing shiny-flag behavior. The foil unlock remains a flag for that edition, not an independently transferable foil copy. A trade moves the exact edition copy; it does not transfer that permanent flag. Recycling requires a spare of the same edition and preserves its last copy. Special editions cannot be crafted; Signature cards retain their existing crafting rules.

## Inventory and signed history (specification version 4)

`Editions.lua` is the source of truth. Variant keys use `edition:<npc-id * 10 + slot>`, for example `edition:6391` and `edition:6392`. They keep their original creature/model ID and set but do not enter `page.cards`. The generated shared catalog lists their `baseKey`, edition title, and weighted family entries under `catalog.editions`.

Counts, shiny flags, trades and snapshot data use those exact keys. There is no nested inventory migration and no new event field. The event text, chain hashes and signatures retain their prior format. Before the first edition-aware boss attempt or pack opening, the addon records `mode / editions1` (count=0, tape=0). Replay persists `state.editions=true` without changing Casual/Ranked mode. Earlier events retain their old meaning; old server state JSON without this field remains valid. Edition events require upload `specVersion: 4`; the server continues accepting versions 2 and 3 for legacy histories without editions.

In Ranked, the edition draw is:

```
1 + (first_32_bits(SHA256("edition-v1|" + tapeEntry)) modulo 1000)
```

For each activated drop or pack card, both sides select the still edition for 1–150, the animated edition for 151–200, and Signature for 201–1000. The edition choice consumes no extra tape entry and is independent of the existing drop/shiny/pack calculations. The server validates the exact key, including Signature. Pity and attempts remain keyed by the base source; every successful edition resets the same source's pity. An edition cannot be used as a separate miss source or crafted into existence.

Base sets, card milestones, statistical unique-card counts and scores group editions by creature. Owning multiple editions adds no extra base-card points. The best owned shiny finish supplies the existing single shiny bonus for that creature. Scoring is rules version 2; a server rebuild refreshes existing derived scores when deploying this change.

## Testing and rollout

`tests/parts/22-collectible-editions.lua` covers native icon placement, all eight families, exact-copy ownership/trades/recycling and locked UI selection. `tests/editions.test.js` runs real Lua histories through the shared rules and server, including a Blackfathom completion, Ranked uploads split across batches, and a correctly signed forged edition rejected by the server. Existing pack and companion sync tests cover the version-4 path too.

The original edition rollout needs the matching server/catalog and companion. The 0.4.0 pose refinements change only addon artwork: card keys, drop weights, catalog version and inventory are unchanged. Gifts also use existing server-checked transfers. Existing histories and collections are retained; nobody is granted variants retroactively. Actual model composition and animation timing need in-game review.
